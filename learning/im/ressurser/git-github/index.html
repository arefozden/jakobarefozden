Hva er Git?

Git er et system for versjonskontroll. Det holder oversikt over endringer du gjør i filene i et prosjekt.

Med Git kan du blant annet se historikken i prosjektet og gå tilbake til tidligere versjoner.

↑ Til toppen

Hva er GitHub?

GitHub er en nettbasert tjeneste der du kan lagre Git-prosjekter, dele kode og samarbeide med andre.

Repository

Et repository, ofte kalt et repo, er prosjektmappen som Git holder oversikt over.

Et repository kan inneholde kode, bilder, dokumentasjon og andre filer som hører til prosjektet.

Vanlig Git-arbeidsflyt

En enkel arbeidsflyt kan se slik ut: 

git status

git add .

git commit -m "Oppdater forsiden"

git push

En enkel huskeregel

1. Gjør endringer

2. Test

3. git status

4. git add .

5. git commit -m "Beskriv endringen"

6. git push

git status

Viser hvilke filer som er endret, og hvilke filer som er klare for commit. 

git status

git add

Legger endringer til staging-området før du lager en commit. 

git add .

git push

Sender lokale commits til GitHub. 

git push

git pull

Henter de nyeste endringene fra GitHub. 

git pull

git clone

Hvis et prosjekt allerede finnes på GitHub, kan du laste det ned med git clone. 

git clone URL-TIL-REPOSITORY
↑ Til toppen

git commit

En commit lager et lagringspunkt i prosjektets historikk. 

git commit -m "Legg til ny ressursside"

Gode commit-meldinger

Commit-meldingen bør kort forklare hva som faktisk er endret. 

git commit -m "Legg til Python-ressurser"

git commit -m "Rett feil i navigasjonen"

git commit -m "Oppdater design på forsiden"

Dårlige commit-meldinger

git commit -m "ting"

git commit -m "nytt"

git commit -m "fix"

Slike meldinger gjør det vanskelig å forstå prosjektets historikk senere.

GitHub Pages

GitHub Pages kan brukes til å publisere statiske nettsider direkte fra et repository.

Det passer godt for nettsider som bruker HTML, CSS og JavaScript.

Publisere en nettside

  1. Opprett eller åpne repository på GitHub.
  2. Last opp eller push nettsiden til repository.
  3. Åpne Settings.
  4. Velg Pages.
  5. Velg hvilken branch som skal publiseres.
  6. Lagre innstillingene.
  7. Vent til GitHub oppretter nettadressen.

Før du publiserer

  • Fungerer nettsiden lokalt?
  • Er alle filene lagret?
  • Fungerer lenkene?
  • Er det feil i Console?
  • Er filstrukturen ryddig?

Vanlige problemer

Hvis Git eller GitHub ikke fungerer som forventet, start med å lese feilmeldingen.

  • Er Git installert?
  • Er du i riktig prosjektmappe?
  • Er repository koblet til riktig remote?
  • Har du internettforbindelse?
  • Har du hentet de nyeste endringene?

Kontroller hvor du er

Mange feil skjer fordi terminalen står i feil mappe.

Kontroller alltid at du arbeider inne i riktig prosjekt før du bruker Git-kommandoene.

Hvis push ikke fungerer

Det kan hende at GitHub har endringer som du ikke har lokalt.

Da kan det være nødvendig å hente de nyeste endringene først. 

git pull

git push
