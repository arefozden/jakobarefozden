API fundamentals

HTTP requests, JSON responses, asynchronous JavaScript and error handling.

An API defines how applications exchange information. REST-style HTTP endpoints often return JSON. GET retrieves information; HTTP status codes indicate the outcome. Check response.ok before parsing a response.

Practical example

async function load(url) {
  const response = await fetch(url);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}

Public data

Weather forecasts, exchange rates, prayer schedules and time-zone data.

Weather, currency and prayer-time services supply different kinds of data. Weather forecasts are estimates, reference exchange rates are not bank prices, and prayer times depend on calculation methods. World Clock uses browser time-zone capabilities rather than an external API.

Practical example

const time = new Intl.DateTimeFormat("en-GB", {
  timeZone: "Europe/Oslo", timeStyle: "short"
}).format(new Date());

Reliability

Input validation, loading states, network errors, caching and provider limitations.

Network requests can fail because of connectivity, CORS, rate limits or changed endpoints. Provide loading and error states, validate incoming data, and label cached results with their date. Never silently substitute invented values.

Practical example

try {
  const data = await load(url);
  // Validate and render data.
} catch (error) {
  status.textContent = "Unable to load data.";
}

Try it yourself

Test an application offline and check that its error message is useful.

Static hosting

Building API-driven frontends for GitHub Pages without exposing private API keys.

GitHub Pages serves static files. Browser requests require a provider that permits cross-origin access. Secret API keys must remain on a trusted backend, not in JavaScript or a public repository.

Practical example

Browser → public API (CORS permitted)
Browser → trusted backend → private API (secret stays server-side)
